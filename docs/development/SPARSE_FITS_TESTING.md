# Testing Infrastructure for Sparse HEALPix Maps

## Background: The Regression

**Issue**: v0.5.0 broke sparse HEALPix files using EXPLICIT indexing
- **Symptom**: "Map contains no valid HEALPix values" panic
- **Root Cause**: Sparse maps initialized with `f64::NEG_INFINITY` instead of `HPX_UNSEEN`
- **Impact**: All sparse pixels marked as invalid, rendering failed

## Test Coverage

### Unit Tests (in `src/fits.rs`)

#### 1. `test_sparse_fit_explicit_indexing()`
Tests that explicit indexing sparse FITS files load correctly:
- Loads minimal NSIDE=1 sparse FITS with 4 populated pixels (indices 0, 3, 6, 9)
- Verifies populated pixels have correct values (1.0, 2.0, 3.0, 4.0)
- Verifies unpopulated pixels are marked HPX_UNSEEN

#### 2. `test_sparse_map_regression_fix()`
Regression test for the specific v0.5.0 bug:
- Verifies no pixels are initialized with `f64::NEG_INFINITY`
- Confirms 4 populated pixels and 8 unseen pixels
- Guards against reintroduction of the bug

### Test Fixture

**File**: `tests/fixtures/sparse_nside1.fits` (8.5 KB)
- NSIDE=1 sparse map (12 pixels total)

## How Sparse FITS Files Work

### EXPLICIT Indexing
```
FITS Binary Table Layout:
┌─────────────┬─────────┐
│ PIXEL (J)   │ T (E)   │  <- Column headers
├─────────────┼─────────┤
│ 0           │ 1.0     │  <- Only populated pixels stored
│ 3           │ 2.0     │
│ 6           │ 3.0     │
│ 9           │ 4.0     │
└─────────────┴─────────┘

When expanded to full map:
Pixel 0: 1.0
Pixel 1: HPX_UNSEEN
Pixel 2: HPX_UNSEEN
Pixel 3: 2.0
...
```

### Important Constants
- `HPX_UNSEEN = -1.6375e30` - Sentinel value for unobserved pixels
- `NEG_INFINITY = -inf` - **INCORRECT** for sparse maps (the bug)

## Key Implementation Details

### From `src/fits.rs` - `read_healpix_column()`

**For sparse maps (EXPLICIT indexing):**
1. Read both PIXEL and data columns together (preserves correspondence)
2. Initialize full map with `HPX_UNSEEN` (not `NEG_INFINITY`)
3. Populate sparse pixels from parallel processing
4. Return full expanded map

**Critical fix:**
```rust
// CORRECT ✓
let mut full_map = vec![crate::healpix::HPX_UNSEEN; npix];

// WRONG ✗ (the v0.5.0 bug)
let mut full_map = vec![f64::NEG_INFINITY; npix];
```

## Preventing Future Regressions

1. ✓ Unit tests verify sparse maps load correctly
2. ✓ Regression test prevents NEG_INFINITY reintroduction
3. ✓ Real FITS test file provides ground truth
4. Add to CI/CD to prevent regression in future versions

## Caching Considerations

Sparse FITS files are cached by column. Care should be taken when:
- Modifying sparse FITS handling code
- Changing column reading logic
- Cache should be cleared during development: `rm ~/.cache/map2fig/fits_col_*`
